Security activation requirements

  1. Staff identity. Use an approved authentication provider with verified teacher accounts, multifactor authentication where possible, and server-validated sessions.
  2. Permission separation. Define teacher, safeguarding lead, and administrator roles. Deny access by default; verify role and school scope on every sensitive API request.
  3. Backend integration. Identify and update the live multiplayer API source and its database. Never rely on a hidden page, client-side role switch, learner PIN or public JavaScript as access control.
  4. Reporting workflow. Agree who receives reports, how concerns are escalated, what evidence is retained, and how long it is kept.
  5. Data minimisation. Limit data returned to the staff role's duties. Avoid collecting full student names or unnecessary message content.
  6. Testing. Verify access is denied to signed-out users, students, unassigned teachers and expired sessions; test audit logging and safe error messages.

Do not put production passwords, database connection strings, administrator keys or student records in GitHub files or browser JavaScript.
